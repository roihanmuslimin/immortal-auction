# Task A1: scaffold, lint, CI skeleton, and import workflow

Requires: nothing. Required by: every later task.

## Acceptance criteria and evidence

1. **CI pipeline runs green.** Workflows exist in `.github/workflows/ci.yml`. Status: not claimed until a real GitHub Actions run completes.
2. **A deliberate boundary violation fails lint.** `tests/lint/rules.test.mjs` (boundary tests with fixtures in `tests/fixtures/lint`).
3. **Display-text, random-or-time and floating-point rules each have a failing fixture.** Same test file (`display text`, `purity` tests).
4. **Build outputs a bundle and a size report.** `tools/build.mjs`, `tools/size-report.mjs`, `tests/build/size-report.test.mjs`. The esbuild call itself runs only where esbuild is installed.
5. **Import validator rejects path traversal, absolute paths, symlinks, oversize archives, files outside the allowlist, protected files and secret patterns.** `tests/import/validate-zip.test.mjs`, `tests/import/apply-import.test.mjs`, `tests/import/interop.test.mjs`, `tests/import/workflows.test.mjs`.
6. **All tests run with Node alone.** `node --test "tests/**/*.test.mjs"`; zero dependencies.

## Known limits

- The linter uses a small tokenizer, not a full JavaScript parser. Regex-versus-division detection is heuristic.
- Floating-point results that come from the division operator are not caught statically. Task A7 adds integer-division helpers and property tests.
- The display-text rule is a heuristic (two or more words in a string literal).
- `package-lock.json` is not committed; the CI build job generates one and uploads it as an artifact. Commit it once reviewed.
- Workflow actions are pinned to major versions (`@v4`), not commit SHAs.
- Cross-engine checks (Chromium, Firefox, WebKit) start in task A2.
